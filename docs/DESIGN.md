# Fathom 产品体验与视觉合同

更新：2026-09-22。本文件是产品体验的权威约束。五页布局、信息层级、详情、状态与 R3 视觉已有产品实现；ISS-026 的原型已获用户确认，ISS-027 模块化已交付。ISS-028/077 的剩余 Tauri 视口与键盘实测、发行首次体验仍须按 [TASKS](TASKS.md) 验收；不把剩余验证理解为重做原型或整套 UI。下文保留目标合同和设计来源，现状以 [ARCHITECTURE](ARCHITECTURE.md) 为准。

## 体验原则

- 先回答“发生了什么”，再给图表和证据。剩余空间、目录变化和可回收空间是不同概念，不能混用。
- 一个主任务对应一个显著主操作；全局“立即扫描”不应压过当前页面的“查看变化/定位目录”。
- 用户随时看得见监控范围、数据时间和覆盖质量；缺失/部分结果/未知不能伪装成零。
- 目录事实与用途解释逐层展开。近期没有识别结果时不显示虚构用途或待办占位区块。
- 颜色必须配合文字/符号；所有主要操作可键盘到达；文件名只当文本渲染。

## 信息架构与页面职责

保留总览、变化、分布、大文件、设置五个主入口。目录详情是跨页共享的侧面板，在较窄桌面窗口改为全宽详情，返回时保留筛选和滚动。远期智能解释嵌入目录详情与变化摘要，不新增默认聊天首页。

| 页面 | 首屏必须回答 | 内容顺序 | 主要动作 |
|---|---|---|---|
| 总览 | 本次比上次变化多少，是否需要关注 | 数据时间/范围与质量 → 变化结论 → Top 变化 → 卷容量与趋势 → 最近扫描状态 | 查看变化；无快照时开始首扫 |
| 变化 | 哪些目录解释这次变化 | 对比区间与可比性 → 净变化及口径 → 可排序变化表 → 选中目录证据 → 报告档案 | 选目录查看详情；报告在次级入口 |
| 分布 | 当前容量集中在哪里 | 快照时间/根 → 面包屑 → 子目录表与占比图 → 目录详情 | 下钻、返回上层、Finder 显示 |
| 大文件 | 最近修改的哪些大文件值得查看 | 时间/阈值/范围 → 查询状态与更新时间 → 文件表 | 明确点击查询；打开目录 |
| 设置 | 监控什么、何时运行、如何恢复 | 监控范围与权限 → 计划/后台状态 → 数据与版本 → 诊断/卸载 → 可选智能分析设置 | 保存/恢复默认/查看授权说明 |

“今日摘要”仅在日期语义成立时使用；一般称“最近变化”，始终标出实际 a → b 时间。同日补扫不会产生新的跨日基线，原日期的选择若失效须自动回退并告知用户。

## 三条关键用户旅程

1. **首次安装**：欢迎及本机存储说明 → 选择/确认单个监控范围 → 说明后台扫描与权限（可暂不授权）→ 首扫进度 → 基线已建立，展示分布。只需一个有效快照即可用分布；差分区说明等待下个日期，不报失败。
2. **日常定位**：总览“最近增长 X（范围/质量）” → 变化表选中目录 → 详情中的历史与来源证据 → Finder。前三步最多三次主要导航；不要求用户在五页来回查路径。
3. **恢复与理解**：失败/权限受限/服务未连接提示原因 → 重试或打开对应设置说明 → 保留上次有效数据并注明时间。远期“解释这个目录”先显示证据与发送范围，再分析，结果可驳回/重跑。

## 状态合同

| 情况 | 用户看到的内容 | 可执行动作/恢复结果 |
|---|---|---|
| 无快照 | 为什么需要基线、范围、未采集 | 开始首扫；不展示假 0 趋势 |
| 仅一个有效快照 | “基线已建立”；分布可用；差分需不同日期 | 查看分布；查看下次计划 |
| 扫描中 | 阶段/已耗时/仍在运行；上次数据时间 | 禁止重复扫描；支持取消后才显示取消；不伪造百分比 |
| 部分覆盖 | 受限/失败类别与影响，最后有效时点 | 查看权限说明或重扫；缺失目录不叫“已删除” |
| 扫描失败 | 失败原因、保留上次有效快照 | 重试/查看诊断；不能只显示完成时间 |
| 数据区域加载 | 本区域加载提示，保持高度 | 离页可取消；不让其他区域失效 |
| API/服务失败 | 明确连接/版本/请求错误 | 区域重试；发行版提供恢复入口，面向用户不露 `main.py install` |
| 无匹配结果 | 条件及范围、最近查询时间 | 调整条件；与读取失败区分 |
| 快照被替换/淘汰 | 说明所选日期的数据已更新/不再可用 | 选择最近有效快照；清除旧结果 |
| 历史缺点 | 图中 gap；文本说明阈值/未扫描/未知 | 可查依据，不补零 |
| 大结果/截断 | 当前展示数/总数或已截断标记 | 分页/筛选；图表“其他/未展示”可见 |
| Agent 不可用/分析中 | 基础事实照常显示；单独分析进度或原因 | 取消/重试/使用本地识别 |
| Agent 结果过期/未知 | 所绑定快照、缺失证据与限制 | 重新分析；用户标签不丢失 |

同一状态必须覆盖总览、顶栏、tray 与通知。扫描成功、日报不可用、通知失败分别表达。通知阈值与页面告警来自同一设置事实；保存失败必须保持旧值可辨。

## 视觉系统目标

- 保留克制的浅色桌面风格和线条 SVG，避免全屏大卡片重复包装。导航与工作区边界清晰，表格承担比较、详情承担解释。
- 基础令牌沿用 `--bg #f5f6f8 / --card #fff / --border #e4e7ec / --text #1a2233 / --muted #6b7486 / --primary #2f6fed / --danger #d64545 / --ok #2e9e5b`；增加 warning、焦点、选中、禁用语义前先在原型中验证对比度。
- 字阶：页标题 22–24px、主结论 28–32px、区块标题 15–16px、正文 14px、表格 13px、辅助 12px；路径等宽、数字等宽对齐。禁止所有信息同权重。
- 间距以 4/8/12/16/24/32px 为尺度；工作区内边距 24px，区块间距 24px；控件高度建议 32px，主要按钮 36px。边框与轻阴影用于分组，圆角 8–12px。
- ≥1200px 可使用 168–184px 带文字导航和右侧详情；980–1199px 使用紧凑导航，详情改全宽层以免挤压表格。现有最小窗口为 980×640，M1 必须在此尺寸与 1220×820 实测。
- 核心表格只截断中间路径，名称/末级可读，完整路径可复制/查看；不让长路径撑破布局。表头与数字列对齐，正数 `+`、负数 `−`、缺失 `—`，0 不着增长/缩减颜色。
- 图标只加 `frontend/icons.js` 的 `ICON_PATHS`，24 viewBox、描边 2、round cap/join；纯图标按钮必须有可访问名称。
- Finder 等行操作在 hover **或键盘 focus** 时可见；键盘上下移动、Enter 打开详情、Esc 关闭后焦点回原行。图表必须有等价表格，不以颜色/鼠标悬停承载唯一信息。
- 远期用途标签区分“本地规则”“Agent 建议”“用户标记”，来源与时间可见；禁止用一个绿色“安全删除”徽章合并复杂判断。

## 原型第二轮：原生 Mac 视觉方向（2026-09-13 用户确认）

用户已试用第一轮原型，认可流程，要求明显提升视觉，并选择“原生 Mac：克制、精致、轻量”。以下保留该轮形成且继续生效的约束；相应原型与产品实装已有交付，原型演示仍只使用合成数据。

- 使用系统字体、稳定的字重和数字对齐；以主结论、页面标题、区块标题、辅助说明形成层级。减少加粗文字和描边的竞争。
- 侧栏与工作区保持轻微材质/背景差异，选中项清晰但克制。顶栏采用桌面工具栏式对齐，主操作和次操作分组；原型场景选择器保持可辨但不压过内容。
- 表格作为主要工作区，统一行高、列宽、对齐与 hover/focus/选中状态；减少重复外框，利用分隔线与留白建立分组。正负变化仍配文字与符号。
- 图表使用清晰坐标、精简网格和统一留白，缺失点保持间断；不以装饰性渐变或巨大数字代替信息。路径、来源和采集质量的可读性优先。
- 目录详情形成清楚的标题区、事实区、趋势区、次要操作区；窄窗覆盖层完全不透明，边缘和滚动行为稳定，Esc 返回焦点继续有效。
- 不新增聊天页、虚构 Agent 分析或生产操作。现有令牌与浅色基调保持兼容；视觉效果必须在 980×640 和 1220×820 实际浏览器中核对，提交同场景前后对照与关键状态截图。

## 原型第三轮：Fathom 视觉签名（2026-09-18 用户确认方向，ISS-072 已实装进产品）

用户确认第二轮“总体已经好非常多”“比较优雅”，流程与图标没有问题，同时认为整体仍偏中规中矩，希望增加个人特色。第三轮保留第二轮的布局、信息层级和原生 Mac 克制感，只补足来自产品名字与任务的稳定识别符号。**2026-09-18 用户评审产品 UI 后选定「落地 R3 测深视觉签名 + 仪器风数字排版」组合，ISS-072 将下列合同从 `prototypes/ux/` 原型移植进 `frontend/` 产品实装**（token 全面替换通用蓝、侧栏深度环字标替代船锚、总览主结论背景等深线、图表主色海沟蓝、全站 tabular-nums 数字等宽）；扫描中旋转深度环指示随后已由 ISS-073 接线，并复用 `frontend/icons.js` 的集中出口；不是待实现项。

- 视觉母题采用“测深/等深线”：以低对比等深线、同心探测纹和短深度刻度表达空间从表面到证据的层次。它们只能出现在侧栏品牌区、总览主结论背景、选中态或关键图表的少量位置，不铺满所有卡片。
- 将 Fathom 标记抽象为一个可缩放的“深度环”：开放圆环、中心探针与一处刻度缺口组成，保持线条 SVG 语言；可用于应用字标、加载/扫描状态和当前目录定位，不替换各功能图标。
- 色彩沿用浅色系统基调，增加一组低饱和“海沟蓝—矿物青”强调色。只允许主动作、当前选择和深度环使用；成功、警告、错误仍使用既有语义色，避免品牌色冒充状态。
- 动效限于 160–240ms 的环形探测、等深线轻微显现和选中深度过渡；遵守 `prefers-reduced-motion`，静止时仍能理解全部信息。
- 不加入写实海浪、船锚、指南针、玻璃霓虹、大面积渐变或营销插画。特色不能降低表格密度、长路径可读性、对比度、键盘焦点和三种视口稳定性。
- 验收除当时的 99 项流程门外，增加品牌元素稀疏度、语义色不混用、减少动态偏好和同场景前后截图核对。ISS-026 用户确认已记录于下段；后续变更沿用合同，不重复要求原型确认。

## Logo 与应用图标（双形态体系）

App 图标人工门（ISS-045）经历了两次用户确认，形成**双形态体系**（DEC-023）：

**App 图标 = 层叠深潭（位图系，正式）**：用户 2026-09-19 在 Logo 设计会话选中第二轮「层叠深潭」并要求只取核心——象牙白 squircle 底板 + 蓝青色不规则水滴状四层嵌套等深阶地向午夜蓝中心下陷 + 顶部测深刻痕，哑光层次质感（参考 FaroPDF 的层次感与 Funes 的轮廓表达，未复制主体；原稿与提示词见 `assets/brand/`，由内置 image_gen 生成）。落地为 `scripts/build_app_icon.py` 本地 Pillow 抠图（清暖灰环境背景 → 满幅 1024、透明四角圆角约 17%、边缘白雾清理），可重复、不调用生成模型；`build_icons.sh` 派生全尺寸 iconset/icns；`apple-touch-icon.png` 同源。历史注记：PR #116 曾以线条深度环作为 App 图标（同日清晨），当日由深潭替换。

**界面小尺寸 = 深度环（矢量系）**：菜单栏 tray（22pt 灰度 template）、侧栏字标（`frontend/icons.js` brandRing）、浏览器 favicon（`frontend/favicon.svg`）保留 R3「深度环」线条形态——海沟蓝 squircle 底 + 白色开放环（右上 50° 缺口）+ 中心探针 + 亮矿物青刻度（`#82c8c2`）。取舍：深潭四层结构在 22pt 灰度下不可辨；等深线纹理保留在总览页背景。几何声明在 `apps/desktop/src-tauri/icons/icon.svg`（24 viewBox 与 brandRing 逐参数对应，仅描边加粗 2.4/2.2）；tray 由 `make_tray_icon.py` 距离场生成（透明底白图形，运行时 `icon_as_template(true)` 系统深浅反色），不缩小彩色 App 图标。四处几何由 `scripts/ci_brand_geometry.sh` 门禁保证同步。
